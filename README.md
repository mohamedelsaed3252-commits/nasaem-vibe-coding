# نسايم للمنظفات | Nasaem

**من إنشاء Mohamed El_saed**

مشروع تعليمي وتطبيقي لإدارة محل منظفات: المبيعات والمخزون والتوريدات والديون والمصاريف وصافي الربح الشهري، بواجهة عربية تدعم الكمبيوتر والموبايل.

تم تطوير المشروع ضمن منحة لتعلّم **Vibe Coding**، باستخدام Replit ومساعدة الذكاء الاصطناعي، مع مراجعة المتطلبات واختبار العمليات الحسابية والصلاحيات. عرض شعار Replit يوضح الأداة المستخدمة ولا يعني اعتمادًا رسميًا للمشروع.

## ماذا يقدم النظام؟

- إدارة المنتجات وأقسام المنظفات والبرفانات والورقيات ومستحضرات التجميل.
- تسجيل المخزون بالقطعة، مع تحديد عدد القطع في الكرتونة لكل منتج.
- البحث عن الصنف بالاسم داخل فاتورة البيع؛ الباركود ليس شرطًا لبيع المنتج.
- مسح الباركود بكاميرا الهاتف أو من صورة، وإدخاله بقارئ USB/بلوتوث يعمل كلوحة مفاتيح.
- تسجيل البيع والخصم والملاحظات، وخصم الكميات من المخزون.
- التوريدات ومدفوعات الموردين وربط المتبقي بالديون.
- تسجيل الديون للمحل أو عليه والسداد على دفعات.
- تسجيل الكهرباء والمياه والإيجار والمرتبات والمصاريف الأخرى.
- حساب الربح الشهري من المبيعات الفعلية وتكلفة البضاعة المباعة ومصاريف الشهر.
- حسابات فريق العمل وموافقة المالك والصلاحيات.
- تصدير نسخة احتياطية واستعادتها.

**الربح الشهري = مبيعات الشهر بعد الخصومات − تكلفة الأصناف التي بيعت فعليًا − مصاريف التشغيل المسجلة.**

شراء مخزون لم يُبع بعد ليس مصروفًا يُخصم بالكامل من ربح الشهر. سداد دين المورد ليس خصمًا ثانيًا لتكلفة البضاعة.

## الوصول إلى النظام

الوضع الأساسي هو استخدام النظام عبر الإنترنت من أي شبكة Wi-Fi أو بيانات هاتف، مع استمرار اشتراط تسجيل الدخول والصلاحيات لحماية بيانات المحل. ليس الموقع مقصورًا على شبكة المحل.

يوجد وضع محلي اختياري لعمل الخادم وقاعدة البيانات على كمبيوتر المحل. هذا الوضع مستقل في بياناته عن الوضع المستضاف؛ لا توجد مزامنة تلقائية بين القاعدتين.

## التقنيات

- React وTypeScript وVite، مع واجهة عربية RTL.
- Express وNode.js للخادم.
- PostgreSQL وDrizzle ORM للوضع المستضاف.
- PGlite للوضع المحلي الاختياري.
- Clerk لتسجيل الدخول في الوضع المستضاف، وحسابات محلية للوضع المحلي.
- Zod للتحقق من المدخلات، وOpenAPI/Orval لعقد الواجهة البرمجية.
- pnpm Workspaces لتنظيم الحزم المشتركة.
- ملفات عرض تقديمي قابلة للتعديل من مصدر React، مع تصدير PDF وPowerPoint.


## متطلبات التطوير

1. Node.js 24 وpnpm.
2. تثبيت الاعتماديات من جذر المشروع:

   ```sh
   pnpm install --frozen-lockfile
   ```

3. للوضع المستضاف: قاعدة PostgreSQL وإعداد Clerk، مع توفير المتغيرات المطلوبة في مدير أسرار بيئة التشغيل. **لا تضع القيم في GitHub أو داخل الكود.**

| المتغير | الغرض |
| --- | --- |
| `DATABASE_URL` | اتصال PostgreSQL للوضع المستضاف |
| `CLERK_SECRET_KEY` | مفتاح Clerk السري للخادم |
| `CLERK_PUBLISHABLE_KEY` | إعداد Clerk العام للخادم |
| `VITE_CLERK_PUBLISHABLE_KEY` | إعداد Clerk العام للواجهة |
| `NASAEM_OWNER_EMAIL` | بريد المالك المعتمد، إذا تم ضبطه |
| `PORT` | منفذ الخدمة؛ لكل خدمة منفذ مستقل |
| `BASE_PATH` | المسار الأساسي للواجهة أو العرض |

في Replit تشغّل الخدمات من إعدادات الـ workflows المسجلة لكل artifact. خارجها يجب إعداد منافذ الخدمات ومساراتها ووكيل الطلبات بشكل مناسب؛ وجود الكود وحده لا ينشئ قاعدة بيانات أو حساب Clerk تلقائيًا.

### تشغيل محلي اختياري

```sh
pnpm run nasaem:local
```

أو افتح `start-nasaem-local.bat` على Windows. راجع [الدليل المحلي](README_LOCAL_AR.md) قبل استخدامه. لا تحذف `nasaem-data/` ولا ترفعه إلى GitHub؛ يحتوي بيانات المحل وإعدادات الجلسات.

### فحوصات المشروع

```sh
pnpm run typecheck
pnpm run test:nasaem
node scripts/test-scanner-camera.mjs
pnpm --filter @workspace/nasaem-presentation validate-slides
```

اختبارات الحسابات والمخزون تعمل على قاعدة مؤقتة مستقلة، ولا تعدّل بيانات المحل الحقيقية.

### بناء واجهتي النظام والعرض

```sh
PORT=22615 BASE_PATH=/ pnpm --filter @workspace/nasaem-inventory build
PORT=21779 BASE_PATH=/nasaem-presentation/ pnpm --filter @workspace/nasaem-presentation build
pnpm --filter @workspace/api-server build
```

الأوامر أعلاه بصيغة shell على Linux/macOS؛ على Windows يمكن استخدام المشغّل المحلي. أرقام المنافذ أمثلة للتطوير وليست إلزامًا للنشر.

## حدود مهمة

- الكاميرا المباشرة تحتاج HTTPS أو localhost؛ دعم الفلاش والتركيز يختلف حسب الهاتف والمتصفح.
- تحسين التباين والتركيز لا يعيد تفاصيل باركود مطموس أو صورة مهزوزة بشدة.
- إرسال بريد الموافقة ليس مفعّلًا ما لم تُربط خدمة إرسال بريد؛ توجد إدارة الموافقات داخل النظام.
- أرشفة المنتج تحفظ تاريخ فواتيره. إلغاء البيع يعيد المخزون مرة واحدة ويستبعد الفاتورة من الحسابات بدلًا من حذف التاريخ.
- نجاح الاختبارات لا يغني عن اختبار الهاتف والقارئ الفعليين قبل استخدامهما في المحل.
- حركات PowerPoint تظهر في وضع «عرض الشرائح»، ولا تظهر في PDF الثابت. إعادة تصدير العرض وحدها لا تضيف الحركات؛ يلزم تطبيق سكربت تجهيز الحركات على ملف PowerPoint المصدّر.

## حماية الملفات

حزمة المصدر لا تتضمن الأسرار، أو قاعدة بيانات المحل، أو النسخ الاحتياطية، أو سجل Git القديم، أو المرفقات الشخصية. ملفات PDF وPowerPoint المولّدة محفوظة منفصلة عن تاريخ الكود لتقليل حجمه. إرفاق النسخ الجاهزة بالإصدار عملية منفصلة عن رفع المصدر؛ راجع دليل العرض لمعرفة حالة ملفات التسليم.
